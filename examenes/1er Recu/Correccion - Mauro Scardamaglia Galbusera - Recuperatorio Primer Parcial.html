Sin descuentos.

Observaciones

  • Envio es una clase abstracta en lugar de una interfaz: al no haber estado compartido entre los tipos de envío y los decoradores, lo adecuado es una interfaz.

Transcripción

classDiagram
    class EstadoEnvio {
        <<interface>>
        +void cancelar();
        +void despachar();
        +void repartir();
        +void entregar();
        +void devolver();
    }
    class Envio {
        - EstadoEnvio estado;
        ...
        ⊛A
        ...
    }

    }

        -Envio envio

        -Envio envio
        ⊛A

(En la interfaz, los cinco métodos están encerrados por un corchete rotulado "⊛A"; esa marca se usa como referencia a ese bloque en Envio y en cada estado concreto.)

ACLARACIONES: los 6 estados implementan la interfaz EstadoEnvio, y tienen una relación de agregación con Envio.

Descuentos

  • -0.05 — Los métodos de la interfaz EstadoEnvio no declaran throws TransicionInvalidaException, por lo que el diseño no indica cómo se rechazan las transiciones inválidas.
  • -0.1 — La clase contexto Envio no tiene el método para cambiar de estado (setEstado(estado: EstadoEnvio) o equivalente), que los estados necesitan para producir las transiciones.
